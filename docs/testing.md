# 테스트 전략

## 원칙

- 버그 수정 전 재현 테스트를 작성한다.
- 정상, 실패, 권한, 경계값을 함께 검증한다.
- 테스트를 삭제하거나 완화해 빌드를 통과시키지 않는다.
- 테스트는 외부 MySQL, Redis, PortOne에 우연히 의존하지 않도록 격리한다.

## 계층별 범위

| 테스트 | 대상 |
|---|---|
| 단위 테스트 | 금액 계산, 상태 전이, 권한, 쿠폰 규칙 |
| Repository 테스트 | 복합키, QueryDSL 조건, Soft Delete, 페이징 |
| 통합 테스트 | 트랜잭션, Security, API 요청·응답 |
| 동시성 테스트 | 쿠폰 수량·1인 1장, 상품 중복 구매 |
| 외부 연동 테스트 | 결제 성공·실패·금액 불일치·중복 웹훅 |

## 필수 시나리오

- DRAFT 게시 시 필수값 검증
- 판매자가 아닌 회원의 상품 수정 차단
- 같은 회원의 관심상품·쿠폰 중복 차단
- 쿠폰 100장에 동시 요청 시 정확히 100장 발급
- 같은 상품 동시 구매 시 활성 Trade 하나
- 결제 금액 불일치 시 PAID 처리 차단
- 중복 웹훅 수신 시 한 번만 반영
- 완료되지 않은 거래의 후기 작성 차단

## 명령

```bash
./gradlew clean compileJava
./gradlew test
```

- 현재 테스트 DB는 H2다.
- MySQL 고유 동작, 락, 인덱스 검증 단계에서는 Testcontainers MySQL 도입을 고려한다.
